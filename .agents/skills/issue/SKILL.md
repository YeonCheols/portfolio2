# Issue

이슈를 만들 때는 이 절차만 사용한다. 본문 형식을 임의로 바꾸지 않는다.

## 절차

```
- [ ] 1. 범위 확인: 사용자가 말한 작업만 이슈로 만든다. 다른 작업으로 바꾸지 않는다
- [ ] 2. 이슈만 요청했으면 조사·수정·커밋을 하지 않고 생성만 한다
- [ ] 3. 담당자 계정 확인: gh api user --jq .login
- [ ] 4. 제목과 본문을 아래 문체 규칙으로 작성한다
- [ ] 5. gh issue create --repo <owner/repo> --assignee <login> --title --body
- [ ] 6. 이슈 URL만 보고한다
```

저장소는 현재 git remote의 GitHub 저장소다. 이미 같은 작업의 열린 이슈가 있으면 새로 만들지 않고 그 URL을 알린다.

## 문체

제목과 본문의 문장은 `~습니다` 또는 `~ㅂ니다`로 끝낸다. `~다`, `~한다`, `~했다`, `~이다`로 끝내지 않는다. 한 이슈 안에서 어미를 섞지 않는다.

코드, 식별자, URL, 체크박스 기호는 문장이 아니다. 마침표는 붙이지 않는다.

## 제목

작업 한 줄을 문장으로 쓴다.

```
Vercel 배포 실패를 고칩니다
```

## 본문

```markdown
## 배경

<왜 이 작업이 필요한지. 문장은 ~습니다 또는 ~ㅂ니다로 끝낸다>

## 작업

- <할 일. 문장은 ~습니다 또는 ~ㅂ니다로 끝낸다>

## 완료

- [ ] <끝난 상태. 문장은 ~습니다 또는 ~ㅂ니다로 끝낸다>
```

관련 PR이나 이슈가 있으면 배경에 `#번호`로 적는다. 비밀값, 토큰, `.env` 내용은 넣지 않는다.
