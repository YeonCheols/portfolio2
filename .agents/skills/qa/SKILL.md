# QA

## 범위 파악

`git status`, `git diff` (브랜치 단위면 `git diff origin/master...HEAD`)로 변경 파일과 영향 받는 feature(`src/features/<name>`, `src/pages`, `src/widgets`)를 확인한다.

## 1단계: 정적 검증

PR CI(`.github/workflows/ci.yml`)와 같은 명령을 사용한다. 로컬 QA는 빌드를 추가로 확인한다.

```bash
pnpm lint
pnpm format:check
pnpm type-check
pnpm build
```

- 포맷 실패는 `pnpm format`으로 고친 뒤 다시 검사하고, 자동 수정된 파일을 리포트에 명시한다
- `pnpm lint:fix`는 `yarn format`을 호출하므로 쓰지 않는다

## 2단계: 테스트

```bash
pnpm test
pnpm test -- --coverage   # 변경 파일 커버리지가 필요할 때
```

- 변경된 `src/**` 로직에 대응 테스트가 없으면 "테스트 누락"으로 기록한다 (필요 시 `tdd` 스킬 제안)
- 기존부터 실패하던 테스트는 이번 변경과 구분해 기록한다

## 3단계: 화면 / API 확인

개발 서버는 띄우지 않는다. 사용자가 이미 `pnpm dev` 또는 `pnpm dev:https`를 실행 중일 때만 확인한다.

- UI 변경: 영향 받는 페이지를 브라우저에서 열고, 주요 동작(클릭, 입력, 빈 상태, 다크 모드)을 확인한다
- `src/pages/api/*` 변경: 떠 있는 서버에만 요청한다. 비밀값과 토큰은 출력하지 않는다
- 서버가 없으면 "생략 (개발 서버 없음)"으로 적는다

## 4단계: 코드 리뷰

`review` 스킬(`.agents/skills/review/SKILL.md`)을 변경 범위에 맞는 모드(staged/branch)로 실행하고, 그 발견 사항을 아래 리포트의 "발견 사항"에 그대로 옮긴다.

## 리포트 형식

```markdown
## QA 결과: <통과 | 조건부 통과 | 실패>

| 항목          | 결과       | 비고                |
| ------------- | ---------- | ------------------- |
| Lint          | ✅/❌      |                     |
| 포맷          | ✅/❌      |                     |
| 타입 체크     | ✅/❌      |                     |
| 빌드          | ✅/❌      |                     |
| 단위 테스트   | ✅/❌      | n passed / m failed |
| 화면/API 확인 | ✅/❌/생략 |                     |

### 발견 사항

- 🔴 반드시 수정: <파일:라인 - 내용>
- 🟡 권장: <내용>
- 🟢 참고: <내용>

### 다음 단계

<수정 필요 항목 또는 commit/pr 진행 제안>
```

발견 사항과 생략 이유처럼 근거를 남기는 문장은 `~습니다`로 끝낸다. 발견 사항은 보고만 하고, 수정은 사용자가 요청하거나 명백한 린트·포맷 자동수정에 한해 진행한다.
