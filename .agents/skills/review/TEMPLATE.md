## 코드 리뷰: <🔴 수정 필요 | 🟡 권장 사항 있음 | ✅ 문제 없음>

<변경 요약 1~2문장>

### 발견 사항

발견이 없으면 `- 없음`만 쓴다. 각 항목은 아래 네 줄을 모두 채운다. `테스트`가 비면 그 항목을 쓰지 않는다.

- 🔴 `path:line` — **issue (blocking)**: <문제>
  - 이유: <코드에서 확인한 내용>
  - 테스트: `<spec 경로>` `<테스트 이름>` — <이 케이스가 검증하는 동작. 없으면 "이 동작을 검증하는 케이스가 없음"과 열어본 spec>
  - 제안: <수정 방향>
- 🟡 `path:line` — **suggestion (non-blocking)**: <문제>
  - 이유: <코드에서 확인한 내용>
  - 테스트: <위와 같은 형식>
  - 제안: <수정 방향>
- 🟢 `path:line` — **nitpick**: <문제>
  - 이유: <코드에서 확인한 내용>
  - 테스트: <동작 변경이 아니면 "동작 변경이 아님">
  - 제안: <수정 방향>

라벨은 [Conventional Comments](https://conventionalcomments.org/)의 `issue` / `suggestion` / `nitpick`을 이 저장소 심각도 🔴 / 🟡 / 🟢에 대응한 것이다. `praise`, `question`, `thought`는 쓰지 않는다.

### 테스트 근거

- 실행: `<명령>` → <통과 / 실패 / 실행하지 않음과 이유>
- 대응: <변경한 `*.ts(x)`와 `<name>.test.ts(x)` 짝. 없으면 "없음">
- 예외: <`tdd` 스킬의 테스트 제외 대상이면 파일과 이유. 아니면 "없음">
