# Code Review

## 범위와 권한

| 모드   | 검토 대상                                                                                                                                |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| staged | `git diff --staged`와 관련 호출 경계를 확인합니다. 미스테이징 파일에 의존해야 통과하는 변경인지 구분합니다.                              |
| branch | `git fetch origin` 후 실제 PR base 대비 `git diff origin/<base>...HEAD`를 확인합니다. 원격 PR head와 로컬 HEAD의 일치 여부를 확인합니다. |
| local  | QA 또는 미커밋 리뷰에서 `git diff --staged`, `git diff`, `git ls-files --others --exclude-standard`의 관련 내용을 각각 확인합니다.       |
| ci     | 제공된 diff와 체크아웃 SHA를 읽기 전용으로 검토합니다. 명령 실행·파일 수정·추가 조회는 워크플로가 허용한 범위만 수행합니다.              |

- base/head SHA 또는 로컬 작업 상태, 모드, 제외 범위를 기록합니다. 다른 PR을 리뷰하려고 현재 브랜치를 전환하지 않습니다. 필요하면 격리된 임시 worktree를 사용합니다.
- pnpm-lock.yaml, .next/, coverage/, 생성 파일의 본문은 기본 제외하되 의존성·출력 계약의 영향은 manifest와 소비자에서 확인합니다.
- 리뷰는 보고만 수행합니다. 수정·커밋·푸시·PR 생성·머지는 각각 사용자 요청과 해당 스킬이 필요합니다. 스킬 편집만으로 기존 PR 댓글을 갱신하지 않습니다.
- 프로젝트 로컬 GitHub 인증 설정이 있으면 사용합니다. 인증값과 개인정보 원문을 출력하거나 리뷰에 복사하지 않습니다.

## 1. 목적과 계약

- 연결된 이슈의 본문·댓글, PR 설명, 사용자 지시에서 기대 동작, 수용 조건, 금지 사항과 변경 범위를 정리합니다. 구현자의 설명은 코드로 확인할 가설로 취급합니다.
- 이슈는 사용자 지정, PR 연결 정보, 브랜치·커밋 순서로 찾습니다. 이슈가 없으면 사용자 요구 또는 PR 설명을 기준으로 삼습니다.
- 필요한 자료를 읽지 못했다면 판단에 미치는 영향을 기록합니다. CI에 제공되지 않은 이슈·댓글을 조회한 것으로 쓰지 않습니다.
- 범위를 벗어난 변경의 근거와 실제 영향을 확인합니다.
- 기존 리뷰 댓글과 미해결 스레드는 최신 head에서 재검증합니다. 해결·중복·오탐 여부와 이유를 기록합니다. 불완전한 조회를 전체 확인으로 간주하지 않습니다.

## 2. 데이터 흐름과 공통 소유권

- 생산자 → 검증·변환 → 저장소·캐시·상태 → 화면·API·출력 소비자를 추적합니다. 관련 없는 경계는 억지로 확장하지 않습니다.
- 기존 도메인 모델, 타입, 스키마, 파서, 어댑터, 정책과 공통 함수를 검색하고 경로·호출 관계를 기록합니다.
- 같은 개념의 병렬 모델, 변환 로직 복제, 원본과 파생 상태의 이중 소유를 확인합니다. 공통화가 필요하면 가장 가까운 올바른 FSD 소유 위치와 교체할 소비자를 제안합니다. 재사용 가능성만으로 shared 이동을 요구하지 않습니다.
- 기존 동작 보존이나 fallback은 실제 공개 계약, 현재 소비자, 저장 데이터와 마이그레이션 요구로 판단합니다. 근거 없이 호환 분기·조용한 복구·재시도를 권하지 않습니다. 운영 중인 계약을 사전 출시 기능처럼 취급하지 않습니다.

## 3. 불변조건과 영향 시나리오

관련 항목만 골라 기대 결과와 근거를 적습니다. 각 항목은 확인·위반·미확인·해당 없음으로 구분합니다. 테스트 통과만으로 전체 경계를 확인했다고 쓰지 않습니다.

- **이력서·콘텐츠·변환**: 원본·출처 보존, ID 유일성, 참조 무결성, 기간·누락 값, 선택·조합 후 필드 손실, 출력 간 의미 보존을 확인합니다. 내부 개인정보의 라우트·API·공개 파일·클라이언트 번들 노출을 확인합니다. 미구현 MCP·변환기를 구현된 경로처럼 평가하지 않습니다.
- **API·인증·외부 연동**: 권한 경계, 요청·응답 계약, 검증·정규화 소유권, 빈 값·부분 응답·실패와 민감정보 노출을 확인합니다.
- **SWR·Zustand·비동기 UI**: 캐시 키의 사용자·조건 분리, 늦은 응답의 최신 상태 덮어쓰기, 중복 요청, 실패 후 상태, effect·구독·부모/자식 갱신 순환을 확인합니다. 동일 입력의 반복 갱신을 막는 기준을 확인합니다.
- **공통 UI·라우트**: SSR의 브라우저 API 접근, 로딩·빈 값·오류 상태, 접근성, dark:와 SEO, 다른 소비자의 회귀를 확인합니다.
- **설정·의존성·배포**: 타입 검사 외에도 모듈 해석, 경로 별칭, 번들·빌드·런타임, 서버/클라이언트 환경변수 경계, 배포 명령과 산출물을 확인합니다. 문서·설정의 TDD 예외는 운영 영향 검토의 면제가 아닙니다.

보안·데이터 손실·인증·공개 노출·운영 배포 등 중요한 경계를 검증하지 못했다면 필요한 최소 검증을 지정합니다.

## 4. 코드와 테스트 근거

- 비밀값 하드코딩, `.env*`·`cert/` 포함, `NEXT_PUBLIC_`에 토큰 노출, 검증되지 않은 `dangerouslySetInnerHTML` 입력, API 오류 응답의 스택·토큰·내부 URL 노출을 우선 확인합니다.
- AGENTS.md의 FSD 방향·공개 index·import 규칙, 타입·오류 처리, cn, dark:, 키보드 조작과 alt를 확인합니다. 실제 영향이 있는 번들·이미지·리스트 key 문제를 확인합니다.
- src/ 실행 동작 변경에 대응하는 테스트가 없으면 TDD 규칙 위반으로 차단합니다. 파일 존재만 보지 말고 수용 조건과 경계 동작을 검증하는지 확인합니다. 검색 경로와 누락된 케이스를 적습니다.
- 테스트의 .env·실제 네트워크·현재 시각·순서 의존, assertion 약화를 확인합니다. TDD 순서의 증거 없이 Red를 실행했다고 추정하지 않습니다.
- 발견마다 코드 위치, 위반 계약, 발동 조건·영향과 테스트 근거를 적습니다. 테스트 부재·실행 불가를 이유로 코드에서 확인한 결함을 숨기지 않습니다.
- 테스트 항목은 기존 케이스·실행 결과, 검색으로 확인한 케이스 누락, 또는 구체적인 재현/추가 검증 방법으로 채웁니다. 미실행은 명시하고 제안한 테스트를 통과한 것으로 쓰지 않습니다.
- 문서·MDX 본문·설정 등 TDD 예외는 파일과 이유를 기록합니다. 코드·계약 근거 없는 결함은 지적하지 않습니다.
- 변경 경로의 테스트부터 필요에 따라 타입·lint·빌드·통합 검증으로 넓힙니다. 같은 SHA와 관련 설정에서 수행한 결과는 범위를 확인해 재사용할 수 있습니다. 개발 서버는 자동으로 띄우지 않습니다.

## 5. 심각도와 결론

- **차단**: 확인된 보안 문제, 데이터 손상·손실, 명백한 동작 오류, 운영 장애, 테스트 없는 실행 동작 변경을 보고합니다. 중요한 경계의 판단 근거가 빠진 경우는 결함 확정과 구분해 검증 보류로 보고합니다.
- **권장**: 코드 근거가 있는 비차단 경계 누락, 접근성·FSD·유지보수성 개선을 보고합니다.
- **참고**: 동작을 바꾸지 않는 사소한 의견만 적습니다. 취향과 추측은 제외합니다.
- 결론은 🔴 수정 필요, 🔴 검증 보류, 🟡 권장 사항 있음, ✅ 문제 없음 중 하나입니다. 검증 보류에도 근거·실패 시 영향·최소 검증을 지정합니다. 중요하지 않은 미확인 사항까지 모두 차단하지 않습니다.
- 중요한 미확인 항목이나 잘린 diff가 남으면 ✅ 문제 없음으로 결론 내리지 않습니다. 발견이 없어도 미확인 사항에 한계와 다음 검증을 적습니다.
- 기존 review-gate는 본문 전체에서 차단 아이콘을 검색합니다. 차단이 없는 결과에는 해당 아이콘을 범례·선택지·해소된 과거 지적에도 남기지 않습니다. 현재 결론과 미해결 차단 항목에만 사용합니다.

## 출력과 후속 처리

- 결과는 [TEMPLATE.md](TEMPLATE.md)만 채웁니다. 한국어 근거 문장은 ~습니다 또는 ~ㅂ니다로 끝냅니다. 해당하지 않는 섹션도 이유 또는 없습니다로 채웁니다.
- 로컬 PR 댓글 첫 줄은 `<!-- ai-review:local -->`입니다. CI 마커 `<!-- ai-review:ci -->`는 워크플로가 붙입니다.
- staged는 차단 시 커밋을 중단합니다. branch는 PR 생성·갱신 흐름에서 댓글로 남깁니다. 일반 local QA는 외부 댓글을 자동 작성하지 않습니다.
- CI는 /review로만 실행합니다. PR 생성·푸시로 자동 실행하지 않습니다. secret·모델·실행 실패 등으로 생략된 리뷰를 통과 증거로 사용하지 않습니다. 200KB 제한 등 일부만 검토했으면 누락 범위를 밝히고 검증 보류로 보고합니다.
- 수정 요청으로 구현했다면 관련 TDD·QA 이후 새 SHA 또는 작업 상태에서 목적·diff·영향 경계·검증을 다시 리뷰합니다. 이전 판정이나 수정 커밋만으로 완료를 선언하지 않습니다. 검증 결과의 재사용 범위와 새로 확인한 경계를 구분합니다.
- 새 head에서는 이전 댓글과 검증을 재평가합니다. 차단 해결 후 PR 댓글이 필요하면 최신 결과를 남깁니다. 자동 수정·커밋 반복 루프를 시작하지 않습니다.
- 머지는 pr 스킬을 따릅니다. 필수 CI 통과와 최신 리뷰의 차단 해소가 모두 필요합니다.
