# Code Review

## 리뷰 대상

| 모드     | 사용 시점                        | diff                                                |
| -------- | -------------------------------- | --------------------------------------------------- |
| `staged` | `commit` 스킬 검증 후, 커밋 직전 | `git diff --staged`                                 |
| `branch` | `pr` 스킬에서 PR 생성 직후       | `git fetch origin && git diff origin/<base>...HEAD` |
| `ci`     | `ai-review` 워크플로             | 워크플로가 제공한 diff 파일                         |

- diff만 보지 말고, 변경된 컴포넌트의 사용처와 테스트 파일을 열어 맥락을 확인한다
- `pnpm-lock.yaml`, `.next/`, `coverage/`, 생성 파일은 리뷰하지 않는다
- 리뷰는 **보고만** 한다. 코드 수정은 사용자가 요청할 때만 (`ci` 모드에서는 절대 수정하지 않음)

## 관점 (우선순위 순)

1. **보안**
   - 비밀값 하드코딩, `.env*` / `cert/` 커밋
   - `NEXT_PUBLIC_`에 토큰·시크릿을 새로 노출
   - `dangerouslySetInnerHTML`에 신뢰할 수 없는 입력을 그대로 넣음
   - API 라우트 에러 응답에 스택, 토큰, 내부 URL 노출
2. **정확성**
   - 로딩/빈 값/에러 상태 누락, 잘못된 early return
   - 클라이언트 전용 API(`window`, `localStorage`)를 서버 렌더에서 가드 없이 호출
   - 날짜·페이지네이션·필터 조건의 경계값
3. **테스트** (`tdd` 원칙)
   - 수정된 로직 파일에 대응하는 `<name>.test.ts(x)` 추가/수정이 있는지
   - 동작 변경·버그 수정에 그 동작을 검증하는 케이스가 있는지
   - 테스트가 `.env`, 네트워크, 시각, 실행 순서에 의존하지 않는지
4. **FSD / 컨벤션** (`AGENTS.md`)
   - 레이어 역방향 import, 슬라이스 내부 직접 import, 같은 레이어 cross-import
   - `pages`에 비즈니스 로직, `shared`에 feature 전용 코드
   - `@/shared/lib/cn` 대신 문자열 이어붙이기, 수동 Tailwind 정렬
   - 의미 없는 이미지 `alt`, 키보드로 쓸 수 없는 클릭 요소
5. **성능**: 불필요한 클라이언트 번들, 큰 이미지를 최적화 없이 추가, 리스트 키로 인덱스만 사용

## 심각도 기준

- 🔴 **반드시 수정**: 보안 문제, 명백한 버그, 배포 장애 가능성, 테스트 없는 동작 변경
- 🟡 **권장**: 엣지 케이스 누락, 접근성 미흡, FSD·컨벤션 위반
- 🟢 **참고**: 동작이 바뀌지 않는 사소한 지적. 추측은 올리지 않는다

근거를 제시할 수 없는 지적은 쓰지 않는다. 지적할 것이 없으면 발견 사항에 `- 없음`만 쓴다.

## TDD 근거

리뷰의 모든 발견은 `tdd` 스킬이 요구하는 테스트와 연결한다. 테스트 근거가 없는 문장은 댓글에 넣지 않는다.

- 발견마다 `TEMPLATE.md`의 `테스트` 줄을 채운다. 비어 있으면 그 발견을 뺀다
- 이유, 제안, 테스트 근거처럼 근거를 남기는 문장은 `~습니다`로 끝낸다. `~한다`로 적힌 근거는 댓글에 넣지 않는다
- `src/`의 동작 변경인데 그 동작을 검증하는 케이스가 없으면 🔴 **issue (blocking)** 이다. 근거는 열어본 `<name>.test.ts(x)`에 해당 케이스가 없다는 것이다
- 문서·MDX 본문·설정만 바뀐 경우는 `tdd` 스킬의 예외다. `테스트 근거`의 예외에 파일과 이유를 적고, 그 변경에 대해 동작 버그를 추측해 🔴/🟡로 올리지 않는다
- 관련 테스트를 실행할 수 있으면 실행하고, 명령과 결과를 `테스트 근거`에 적는다. 실행하지 못했으면 이유를 적고, 실행하지 않은 결과를 통과로 적지 않는다

## 출력

리뷰 본문은 `.agents/skills/review/TEMPLATE.md`를 채운 것만 쓴다. 섹션을 빼거나 다른 제목, 서론, 코드펜스를 붙이지 않는다. 로컬 댓글은 첫 줄 `<!-- ai-review:local -->`, CI 댓글은 첫 줄 `<!-- ai-review:ci -->` 다음에 템플릿 본문만 붙인다.

## 자동 실행 시나리오

| 시점                                  | 실행 주체      | 모드        | 결과                          | 다음 동작                                             |
| ------------------------------------- | -------------- | ----------- | ----------------------------- | ----------------------------------------------------- |
| 에이전트가 커밋 (`commit` 스킬 5단계) | 로컬 에이전트  | `staged`    | 사용자에게 보고               | 🔴 없음 → 커밋 / 🔴 있음 → 중단, 사용자 판단          |
| 에이전트가 PR 생성 (`pr` 스킬 10단계) | 로컬 에이전트  | `branch`    | `ai-review:local` 댓글        | PR URL과 리뷰 요약 보고                               |
| PR 댓글 `/review` (소유자·협업자)     | GitHub Actions | `ci`        | `ai-review:ci` 댓글 생성/갱신 | PR 생성·푸시 자동 실행은 꺼 둠. 🔴가 있으면 체크 실패 |
| 에이전트가 머지 (`pr` 스킬 머지 절차) | 로컬 에이전트  | -           | 최신 리뷰 댓글 확인           | 🔴 없음 + 체크 통과 → 머지                            |
| 사용자가 "리뷰 해줘"                  | 로컬 에이전트  | 상태에 맞게 | 보고 (PR이 있으면 댓글도)     | -                                                     |

- **🔴 처리 루프**: 🔴 보고 → 사용자가 "고쳐" → `tdd`로 수정 → 재스테이징 → 다시 `staged` 리뷰 → 커밋. CI 댓글을 갱신하려면 PR에 `/review`를 단다
- **사용자가 직접 PR을 올린 경우**: 로컬 리뷰는 돌지 않고, CI 리뷰도 `/review` 댓글이 있을 때만 실행된다
- **CI 리뷰가 생략되는 경우**: `/review` 댓글이 없음, `CURSOR_API_KEY` 없음, 에이전트 실행 실패, 포크 PR, 닫힌 PR. 200KB 초과 diff는 앞부분만 리뷰하고 그 사실을 표시한다
- **오탐**: 근거가 틀렸다고 판단되면 사용자에게 근거와 함께 보고한다. 🔴가 댓글에 남아 있으면 머지하지 않는다. 문구를 고친 뒤 리뷰를 다시 실행해 🔴가 없어져야 한다

## 결과 처리

- `staged`: 🔴가 있으면 커밋하지 않고 사용자에게 보고한다. 사용자가 알고도 진행을 요청한 경우만 커밋하고 보고에 남긴다
- `branch`: `TEMPLATE.md`만 채운 결과를 PR 댓글로 남긴다. 본문 첫 줄에 `<!-- ai-review:local -->`를 넣는다
- `ci`: `TEMPLATE.md`만 채운 마크다운을 출력한다 (마커와 댓글 작성은 워크플로가 담당)
- 머지 전 확인: `pr` 스킬의 머지 절차에서 🔴 항목이 해결됐는지 확인한다
