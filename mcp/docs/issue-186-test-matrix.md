## 한계와 미확인

- **권한**: 이 서버는 세션이 활성인지만 확인합니다. 비관리자 거부는 로그인 단계(portfolio-api가 DB에 연결된 GitHub 계정에만 세션을 발급)에 맡기기로 했고 이 서버에 역할 검사를 두지 않습니다. 발급 범위는 portfolio-api가 소유하며 이 작업에서 직접 검증하지 않았습니다.
- **로그인 왕복**: 실제 GitHub 로그인 후 메뉴 도착과 가려던 화면 복귀는 브라우저로 확인하지 못했습니다. 서버 응답과 단위 테스트까지 확인했습니다.
- **재현 잠금**: Storage의 잠금 객체로 인스턴스 사이에서도 막습니다. 실제 Supabase에서 서로 다른 두 연결의 동시 요청이 정확히 하나만 실행됨을 3번 확인했습니다. 잠금은 2분 만료이며, 풀지 못한 잠금은 다음 요청이 치웁니다.
- **목록 비용**: 환경 전체 폴더를 훑는 구조는 그대로이고 폴더 조회를 최대 8개씩 병렬로 처리해 지연을 줄였습니다. 보관량이 크게 늘면 여전히 느려지므로 그때 DB 목록 인덱스를 검토합니다.
- **PDF 응답 크기**: 5MB를 넘으면 본문을 싣지 않고 `pdfOmitted`로 알립니다. 현재 PDF는 약 28KB입니다.
- **시각 확인**: 화면 배치와 애니메이션 모양은 작업 중 브라우저에서 확인했고 자동 테스트는 동작만 검증합니다.
- **실제 Supabase 검증**: 임시 실행 하나로 조회·서명·수정본·재현·삭제를 확인한 결과는 일회성 확인이며 자동 테스트가 아닙니다.
- **MCP 배포와 배포 후 호출**: 이번 범위에 포함하지 않았고 비차단 후속입니다.
