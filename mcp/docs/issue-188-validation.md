# #188 디렉터리 재구성 검증

이 문서는 PR #191의 검증 이력입니다. 후속 테스트 실행기 독립화는 [별도 검증 기록](test-runner-independence.md)에 기록합니다.

## 요구사항과 소유권

- 사용자 확인을 받은 `apps/console`, `apps/backend`, `packages/admin-contracts` 구조로 구성합니다. MCP 루트에 독립적인 pnpm workspace와 lockfile을 유지합니다.
- 소비처는 백엔드 `interfaces/tools`와 `interfaces/admin`으로 구분합니다. 이력서 생성·검증·PDF·아카이브는 `modules/resume`, 설정 연결 진단은 `modules/ai-models`가 소유합니다.
- 공통 메뉴는 `packages/admin-contracts/src/admin-menu.ts` 한 곳에서 정의합니다. 웹과 서버는 `workspace:*` 및 패키지 공개 진입점으로 가져옵니다.
- 서버 파일 81개와 콘솔 파일을 테스트와 함께 이동합니다. 함수·파일 이름, MCP 도구, HTTP 경로, 인증, 응답, 아카이브 키는 보존합니다. 소비처에서 도메인 처리를 호출하는 기존 흐름은 유지합니다.
- 서버 진입점은 `apps/backend/dist/bootstrap/server.js`, 콘솔 산출물은 `apps/console/dist`로 변경합니다. 루트 명령·Docker·Storage 점검 스크립트·CI·문서에서 같은 경로를 사용합니다.

## TDD 근거

- Red: 이동 전 `pnpm exec jest --runInBand mcp/directory-boundary.test.ts`가 종료 코드 1로 실패했습니다. workspace 파일이 없는 기존 구조에서 분리 조건이 거짓임을 확인했습니다. import 오류나 의존성 누락으로 실패한 것이 아닙니다.
- Green: workspace와 앱별 manifest, 공통 계약 패키지, 파일 이동을 적용한 뒤 같은 명령이 종료 코드 0으로 통과했습니다.
- `directory-boundary.test.ts`의 추가 조건은 업무 모듈의 소비처·bootstrap 참조, 관리자와 도구 사이 참조, 콘솔의 서버 소스 직접 참조, 메뉴의 외부 의존성을 검사합니다.
- 기존 테스트는 구현과 함께 이동하고 import와 mock 경로를 갱신했습니다. 원래 경로·인증·아카이브·생성·PDF 시나리오는 유지했습니다.
- `workspace-build.test.mjs`는 실제 CommonJS 산출물과 공통 패키지 연결, 기본 콘솔 경로, 메뉴 화면과 에셋, MCP 도구 등록, 한글 폰트를 사용하는 PDF 생성을 검사합니다. 외부 모델·API를 호출하지 않습니다.

### 발견 사항

- 샌드박스에서는 로컬 HTTP 포트가 `EPERM`으로 차단되어 기존 테스트도 실패했습니다. 권한을 받은 동일 테스트가 통과했으며 시간 제한이나 기대값을 완화하지 않았습니다.
- Vite가 symlink로 연결한 workspace의 CommonJS 공통 패키지를 변환하도록 `commonjsOptions.include`에 해당 산출물 경로를 포함했습니다. 실제 콘솔 프로덕션 빌드와 브라우저 번들 생성이 통과했습니다.
- Next.js 빌드는 기존 React 버전 및 대시보드 GitHub 인증 미설정 경고와 함께 성공했습니다. 빌드가 자동 변경한 웹 JSX 설정과 sitemap은 원래 내용으로 복원했습니다.
- 콘솔 테스트에는 기존 jsdom의 페이지 이동 미구현 메시지가 있으나 100개 테스트가 모두 통과했습니다.

### 다음 단계

### 불변조건과 미확인 사항

- 도구·관리자 URL·생성 스냅샷·아카이브 키와 재현 동작은 기존 회귀 테스트로 확인했습니다.
- 타입스크립트 변환 결과에서 import와 주석·포맷을 제외하면 백엔드 실행 코드 차이는 콘솔 기본 경로와 PDF 폰트 상대경로뿐임을 대조했습니다. 두 경로는 실제 산출물 테스트로 확인했습니다.
- 패키지 의존성을 기존 lockfile 해석 버전 그대로 분리했고 `--frozen-lockfile` 설치가 통과했습니다.
- Docker 이미지 빌드·운영 배포·실제 모델 호출은 실행하지 않았습니다. Docker 구성과 산출물의 로컬 실행은 검증했습니다.
- 백엔드·공통 계약의 기존 Jest 테스트 실행기는 상위 저장소에 유지합니다. MCP를 별도 저장소로 분리할 때는 이 테스트 실행 설정도 함께 이전해야 합니다.

- `directory-boundary.test.ts`에서 manifest 필드와 이전 디렉터리 부재를 나열하던 사례를 제거했습니다. 실제 frozen 설치·프로덕션 빌드·산출물 실행이 해당 패키지 연결을 검증합니다. 의존 방향·명명 규칙·콘솔과 공통 계약 경계의 3개 테스트는 유지했습니다.
- 테스트만 삭제하는 정리이므로 새로운 동작 실패를 만들지 않았습니다. 정리 전 관련 테스트의 통과를 확인하고 같은 범위로 정리 후 회귀 검증했습니다. 앞선 실제 Red·Green 기록은 당시 실행 근거로 유지합니다.
